# Sprint 3.5 — Persona + Agent Split Design

## Overview

Redesign the Agent Armory to properly separate **Agents** (the body — provider, model, options) from **Personas** (the mind — system prompt, strategy, purpose). Both live in the DB. Personas are reusable across agents and providers. The Armory becomes a 3-tab interface: Roster, Personas, Agent Builder.

---

## Core Concept

> **Agent = Body. Persona = Mind.**

- A **Persona** is a provider-agnostic system prompt template. The same "architect" mind can run on Claude, Codex, or Gemini.
- An **Agent** is a runnable body+mind combo: a specific provider + model + persona reference, with its own battle stats.
- **Stats live on Agents** — Claude+architect and Codex+architect earn separate win/loss records.
- **Personas are shared** — many agents can reference the same persona. Editing a persona updates all agents that use it.

## Agent Armory — 3-Tab UI (`/agent-armory`)

### Tab 1: Agent Roster

Read-heavy gallery. The "character select" screen.

- Filter pills: All / Claude / Codex / Gemini
- Search input: filter by name or tags
- Agent cards show: avatar, name, provider badge, persona name, stats (W/L/avg)
- Actions per card:
  - **System agents:** Fork only
  - **Auto/user agents:** Edit → goes to Builder pre-filled, Fork → goes to Builder as fork, Retire
- "+ New Agent" button → navigates to Builder tab (blank)
- Retired agents in collapsed `<details>` at bottom

### Tab 2: Personas

Template library. The "mindset workshop".

- Grid of persona cards
- Persona card shows: avatar, name, description excerpt, tags, "used by N agents" badge
- Actions:
  - **System personas:** view/expand only (Fork coming Sprint 4)
  - **User personas:** Edit (opens inline form), Retire
- "+ New Persona" button → opens creation form inline on the tab
- Persona creation form fields: name, description, system prompt, avatar (emoji picker), tags
- **AI Assist — two entry points:**
  1. **"✨ Generate full persona"** button at top of form — user types a rough idea (e.g. *"paranoid security expert who triple-checks everything"*), AI returns `{ name, description, systemPrompt, tags, avatar }`, pre-fills all fields. User edits and saves.
  2. **✨ button on system prompt field** — expands/improves whatever is already in the field.
- Both AI assist paths hit `POST /generate-persona` on the orchestrator.

### Tab 3: Agent Builder

Character creator. Create new agents or edit existing ones. Navigated to from Roster (Edit/Fork) or "+ New Agent".

**Fields:**
1. **Persona (mind)** — dropdown/search from Personas library, shows avatar+name. "+ Create new persona inline" expands an inline persona creation panel (same form as Personas tab, including AI assist) without leaving the Builder.
2. **Provider (body)** — Claude / Codex / Gemini pill selector
3. **Model Variant** — dropdown populated by provider selection
4. **Agent Name** — text input
5. **Avatar** — emoji picker (optional override of persona avatar)
6. **Tags** — comma-separated
7. *(Future)* **Provider Options** — collapsible section for temperature, etc.

**Modes:**
- **Create** — blank form, "Save Agent" button
- **Edit** — pre-filled, "Update Agent" button
- **Fork** — pre-filled with source agent, `forkedFromId` set, name pre-suffixed with `my-`

## Battle Setup — Step 3 Changes (`/competitions/new`)

Step 3 agent selection replaces the current hardcoded `PERSONAS` array chips.

**New flow:**
1. Provider pills (Claude / Codex / Gemini) — same as today
2. **Search input** — filters agent chips by name as user types
3. **Agent chips** — all non-retired agents for the selected provider, sourced from `GET /api/agents?provider=claude&retired=false`. Chips show agent avatar + name.
4. **"+ Go to Armory"** link — navigates to Armory Builder tab to create a new agent

**Auto-save rule:** If a battle is launched with a provider+persona combination that doesn't match any existing agent, the system auto-creates an agent with `createdBy: 'auto'` before starting. This ensures stats are never lost and every battle combination accumulates a record.

**Runtime wiring:** When a competition starts, `competition-runner.ts` resolves the selected agent's persona from the DB and injects `persona.systemPrompt` into the brief via `adapter.injectBrief(brief, systemPrompt)`.

**Fallback:** If no DB agent is found (e.g. CLI usage without DB), `resolvePersona()` in `claude-personas.ts` is used as before. Backward compatibility preserved.

## Migration Strategy

Migration `0009` must:
1. Create `personas` table
2. Create `agents` table with `personaId` FK
3. Migrate data from `agent_profiles`: extract system prompt → insert into personas, insert agent rows with personaId
4. Drop `agent_profiles` table

The hardcoded `claude-personas.ts` is NOT deleted — it remains as the CLI fallback.
