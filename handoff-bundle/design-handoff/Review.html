Homepage review
/ (Competition Gallery)

Reviewing the page served at localhost:3001/ — the gallery that lists competitions + tournaments, with state/model/category filters, search, and a live API-status dot. Overall: the TRON identity is intact and the information is legible; the main costs are visual hierarchy (nothing on the page reads large) and rhythm (dense rows stacked too tightly). Detailed findings below.

01 What's working

KeepBrand

The TRON layer system is genuinely strong

Fixed background grid (48px / 0.025 opacity), CRT scanlines, corner HUD brackets, and the cyan/blue radial glow stack correctly in layout.tsx. The UX-audit document shows these were all broken a sprint ago — they're now consistent across every route. This is the single biggest reason the product feels like a product and not a dashboard.

KeepSystem

Design tokens are doing real work

getModelColor(), getStateStyle(), FORMAT_BADGES, and the MONOSPACE_FONT / BODY_FONT split are used, not decorative. Model-specific team chips (orange Claude, blue Codex, cyan Gemini) give the matchup row instant readability.

KeepInteraction

Live states feel live

Running competitions get a pulsing cyan border (liveBorder 2s ease-in-out), a pulsing dot + "LIVE" chip, and a tinted card background. This is the single most on-brand detail on the page. The 10-second auto-refresh tied to visibilitychange is the right call.

KeepUX

API-status dot + retry-once fetch

Small but important: the ● online/offline dot in the hero + the two-attempt fetch with a 2s backoff means users actually get a useful error when the orchestrator isn't up, instead of a frozen empty state. Keep this pattern.

02 Critical — fix before launch

CriticalHierarchy

The H1 is too small to carry the page

fontSize: 1.8rem (≈ 34px at 120% root) for "Competition Gallery" is a subheading, not a page title. It sits between a kicker (same uppercase weight) and a stat line (same monospace), so your eye has nowhere to land. On this landing-style view — which is what users see when they hit the app cold — the hero needs to declare itself.

Current hierarchy ladder
kicker 11px  /  h1 ~29px  /  stats 14px  /  filters 11px
Suggestion Push H1 to 3–3.5rem (56–65px). Tighten its line-height to 0.95. Consider dropping the redundant "◆ ARENA4AI | COMPETITIONS" kicker — the TopBar already brands the app; the kicker competes for the same real estate. A short subtitle in BODY_FONT is more useful.
CriticalRhythm

Competition rows are too dense to scan

Each card is padding: 1rem 1.25rem with a 0.65rem gap between siblings. Inside, the title row, matchup row, and score-bars row use 0.82 / 0.67 / 0.55rem type — four sizes stacked in 90 vertical pixels. At rest the page reads as a wall of cyan-on-near-black text.

Example row density (current)
⚔   fizzbuzz-cli   SPRINT   cli   ● LIVE
claude:architect   VS   gemini:speedrunner · ⏱ 2m · 📊 3 runs
🏆 claude:architect ━━━━━━━ 87%    gemini:speedrunner ━━━━ 62%
Suggestion Bump row vertical rhythm: padding: 1.35rem 1.5rem, inter-row gap 0.9rem. Unify internal type to two sizes (title 15px, meta 12.5px). Move score bars out to their own line with more breathing room, and drop the icon prefixes on matchup chips — the colored pill is already the identifier.
CriticalFilters

Three stacked filter rows read as three separate UIs

"State / Model / Category" each get their own row with a tiny all-caps label (0.55rem) followed by a row of buttons (0.65rem). The labels are almost unreadable, the buttons look like secondary nav, and the search input above them sits in a fourth visual tier. Four tiers for "filter this list" is too many.

Suggestion Collapse to a single horizontal toolbar: [ search ]  [ State ▾ ]  [ Model ▾ ]  [ Category ▾ ]. Use segmented controls for State (5 values) — show them inline; keep Model/Category as dropdowns because the option count varies. Drop the mini-labels entirely; the selected value is the label.

03 Major — plan to fix this sprint

MajorType scale

Type sizes below 0.65rem are a dead zone

Counting quickly: state badges 0.52rem (≈10px), filter labels 0.55rem, score-bar labels 0.55rem, timestamps 0.58rem, format badges 0.52rem. At 120% root, everything under 13px in monospace all-caps starts breaking apart — letter-spacing can't save it.

Suggestion Set a floor: nothing smaller than 0.7rem (≈13.5px) in body copy, 0.65rem (≈12.5px) for badges — and only when paired with tighter letter-spacing (1px, not 1.5–2px). Consolidate the four "tiny label" sizes into one token (BADGE_FONT_SIZE).
MajorInformation

Nothing above the fold tells a cold visitor what this is

If I hit / not knowing the product, I see "Competition Gallery · 12 battles completed · 4 agents competing · API online" and then a list. The what is missing. README calls this "the UFC + WWE of AI battles" — none of that personality is on the homepage.

Suggestion Add a one-line subtitle under the H1 in BODY_FONT — something like "Two agents enter. A cross-judge scores their work. Watch them think in real time." Either that or promote the "⚔ New Battle" CTA to a big button in the hero (it's currently only in the TopBar).
MajorEmpty state

The zero-state is underused

First-time users see: ⚔ icon, one line of text ("No battles recorded. Run the first match to claim the arena."), and a single cyan button. This is the most important screen in the product — it's the only chance you have to explain the concept before the user decides whether to bounce. Right now it's smaller than the filter bar.

Suggestion Turn zero-state into an actual onboarding panel: 3 example briefs (fizzbuzz / roman-numerals / debate championship) the user can one-click launch, a 20-second loop of an old run, or a 3-step "how this works" strip. The filesystem already has a briefs/ library — surface it here.
MajorStructure

Tournaments section is orphaned at the bottom

Tournaments sit below a full list of competitions with a 3rem top margin and another full header (kicker + h2 + CTA). On a fresh install with 30 competitions, the Tournaments block is a scroll away and feels like a footnote — even though it's arguably the more strategic view (round-robin is the whole point of a benchmarking platform).

Suggestion Either (a) promote Tournaments into a tab at the top (Competitions | Tournaments) so it's a peer view, or (b) show a compact "Active Tournaments" rail above the competitions list — only the running/pending ones — and keep the full list on /tournaments.
MajorAccessibility

Color contrast on dim text is borderline

#1e4a5a on #050f1e (used for filter labels, timestamps, "·" separators) lands at roughly 2.4:1 — below WCAG AA for any text. It reads as "turned off" visually, which is sometimes the intent, but it's also applied to information users need (timestamps, separators, run counts).

Suggestion Use #1e4a5a only for non-informational glyphs (· dots, inactive filter buttons). For any text the user needs to read, step up to #3d7d94 (TEXT_DIM — ~3.9:1) or #4a8fa8 (TEXT_MUTED — ~5.3:1).

04 Minor polish

MinorCopy

Mixed emoji + icon + glyph vocabulary

The card title row uses ⚔ / 🏆 / 💥 / 🚫 / 📋 for state. The matchup row uses ⏱. Score bars use 🏆 again. Filter search uses 🔍. Zero-state uses ⚔. Every icon on the page is doing different work in different registers (unicode shapes, cartoon emoji, HUD marks). Pick one.

Suggestion Go all-in on HUD glyphs (◆ ● ▸ ⚔ — uniform cyan) and drop the emoji. Or if you want emoji, reserve them for state-change moments only (finished card, victory banner) and use geometric marks for structure.
MinorInteraction

Delete affordance is a ghost

The ✕ delete button renders at color: #0e3050 — nearly invisible on the card until hover. Good for reducing accidental clicks, bad for users who want to tidy up after runs. On first use people won't know it exists.

Suggestion Keep it dim but at least match the state-badge color (#1e4a5a → #3d7d94). Or only show it on card hover — same net behavior, but signals "there is an action here" clearly on desktop.
MinorLoading

Loading state is a single glyph

"⚔ Loading competitions…" centered in 4rem of air. Given how much visual vocabulary the rest of the page has, this looks unfinished. A skeleton of 3–4 ghost card rows would match the brand and prevent the layout from jumping when data arrives.

Suggestion Render 3 .arena-card placeholders at opacity: 0.4 with shimmer on the title and matchup rows. Reuse the scanline keyframe you already have.
MinorLayout

Container is 1400px but rows are list-shaped

You've got 1400px of horizontal space and each competition uses it as a single dense row. On ultrawide monitors the left-aligned title column sits ~600px from the right edge, empty.

Suggestion Either shrink the container to 1100px (more marketing-aligned, matches the 900px the audit flagged as the marketing standard), or switch to a 2-column grid above 1200px — score bars could move into a right-side column instead of stacking below the matchup row.
