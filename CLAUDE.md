## Project Status

Agent Arena is currently in the **blueprint/planning phase**. The repository contains architectural planning documents generated by "The Forge" system but no implemented source code yet. Implementation starts with Phase 0 (CLI orchestrator prototype).

## What This Project Is

Agent Arena is a competitive AI agent orchestration platform that pits multiple AI models against each other to solve structured briefs. Key concepts:
- **Brief**: A structured YAML/JSON problem statement with constraints, deliverables, and a scoring rubric
- **Competition**: Two or more AI teams run in isolated sandboxes against the same brief
- **Judging**: AI cross-judging (Team A's work scored by a different model instance) + automated checkers
- **Synthesis**: Post-competition extraction of best elements from all submissions
- **Forge**: Generates roadmaps, task graphs, and blueprints from synthesis results

## Planned Tech Stack

- **Language**: TypeScript (strict mode) throughout
- **Runtime**: Node.js 20+ (orchestrator, API); Bun optional for adapters
- **Frontend**: Next.js 14+ App Router, TailwindCSS, Radix UI
- **Database**: PostgreSQL with Drizzle ORM
- **Messaging**: NATS JetStream + WebSocket for live event streaming
- **Sandboxing**: Docker containers (Phase 0), Firecracker microVMs (Phase 1+)
- **Monorepo**: Turborepo
- **Validation**: Zod schemas in `@arena/shared`

## Competition State Machine

States flow: `DRAFT → CONFIGURED → LAUNCHING → RUNNING → TIME_UP → COLLECTING → JUDGING → SCORED → SYNTHESIZING → FORGING → COMPLETE`

## Universal Event Schema

Every agent action emits an `ArenaEvent`:
```typescript
{
  eventId: string,
  competitionId: string,
  teamId: string,
  timestamp: ISO8601,
  type: EventType,  // TOOL_CALL | FILE_CREATE | FILE_MODIFY | REASONING | SUB_AGENT_SPAWN | ERROR | TIME_WARNING | TIME_UP | JUDGE_SCORE | SYNTHESIS_COMPLETE | FORGE_COMPLETE
  payload: unknown,
  metadata: Record<string, unknown>
}
```

All model-specific outputs (Claude, Codex, Gemini) are normalized to this schema in their respective `*-normalizer.ts` files.

## Model Adapter Contract

Each adapter implements: `injectBrief`, `startExecution`, `emitEvent`, `collectDeliverables`, `shutdown`
